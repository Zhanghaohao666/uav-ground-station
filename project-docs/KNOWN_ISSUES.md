# 已知限制和未完成项

这些记录来自原始版代码审查及后续修改范围，不表示每个问题都已做完整硬件复测。

- dual-control 版已拆分两套控制：云台主控 9000，算法板主控 9001。只有 `/algorithm`、`/gimbal` 和云台直连 `/live/0` 的画面可发送点选/框选；其他自定义算法流路径需扩展映射，不会猜测控制目标。
- 云台取消/隐藏已停止正在进行的手动按键运动；操作系统失焦、程序崩溃和断网时，设备是否有运动超时保护仍需实板验证。
- 控制 TCP 意外断开不会自动重连，需要手动连接；视频重连不等于控制已恢复。
- 脚本反馈没有完整隔离 task_id；旧任务反馈可能覆盖新任务展示。断线重连还可能保留半包。
- 部分连接/检测状态由本地乐观更新，不能直接作为设备已经执行成功的证明。
- 原电脑本地录像主要覆盖前两路，截图主要覆盖第一路；按需停流会终止本地录像，不自动续录。新增板端录像支持主控全部配置流，不受预览隐藏影响，见 BOARD_RECORDING.md。
- 部分视频总状态由多个接收器共享，不能全部代表某个具体窗口。
- 集群/RViz 等部分页面仍是占位；激光测距完整地面站业务链路未在这些版本中实现。
- 红外预览不等于红外检测、跟踪或测温。新版明确禁用的红外窗口不发送画面跟踪命令。
- v1.01.09-windows 已通过完整 Windows x64 编译、关键视频插件检查及 Qt 主窗口启动检查；这些检查未连接实板。Windows 上的真实 RTSP 播放、实际控制/录像、远距离 MK22 及飞行联调仍需验收。

- 2026-10-18 的 Windows 启动环境候选修复针对“normal 诊断有视频、直接 EXE 无视频”的已确认启动差异；具体触发项和候选包现场效果仍需日志及用户验收，不代表已解决全部黑屏或无线卡顿问题。

- v1.01.10-mk22-rc1 的 Windows 生产接收器 TCP/UDP 解码与队列回归通过，GUI 启动报告在无图形 runner 缺失；不能把原生解码通过当作实际 GUI 播放验收。120ms 网络缓冲和有界显示队列不能替代 MK22 空口容量/丢包/距离实测。

- 离线授权仅限制新版官方运行包的普通复制使用，不追溯旧版、不阻止修改公开源码后重新构建，也不代替板端 RTSP/TCP 身份验证。无可信在线时钟时不能保证绝对防回拨；Windows 重装/主板身份变化需重新授权。生产私钥不进入 CI，真实用户电脑的激活后主界面和播放仍需验收。
