# 点击录像并保存到主控板

源码 `v1.01.09-board-recording` 配套主控 `v1.3.0`。104 板端服务已安装；地面站须重新编译才显示新按钮，未生成 Windows EXE。

## 使用

视频页顶部新增 **板端录像**：首次输入主控 IP 和连接码，点击连接，再单选/多选视频并点击“开始 / 添加录像”。MK22 用 `192.168.2.36`，Wi-Fi 用 `192.168.1.104`。列表区分正在录像和等待视频/重连；正在录像表示近期确有写入帧，不根据按钮点击猜测。

“停止所选”只结束选中的路；“停止全部”结束该主控全部录像，包括板端菜单开始的录像。底部显示剩余容量及任务目录，可复制路径后通过 SFTP 下载文件。

104 连接码单独保存在本地 `板端录像_20261008/104连接码.txt`，不在公开代码或包内。其他主控执行 `sudo cat /etc/uav-record-api/token` 获取本板连接码。“记住连接”保存在该电脑用户设置中；取消勾选后重新连接会移除已存码。

列表按所连接主控的**实际模式**列出全部 7 路固定录像源；dual 两套载荷均可录，单方案不能新开未启用的载荷录像。地面站视频方案按钮只切预览，不更改板端模式或录像选择。自定义预览 URL 不改变录像源。

## 保存及持续运行

默认 `/data/uav-recordings/日期/任务目录/各路名称/`，约 5 分钟一个 MKV，直接保存原压缩码流。各路缺席/断流独立重试。D455 只保存彩色视频，不含深度/IMU。

隐藏预览、全屏、切方案、关闭面板、退出地面站或断网，板端录像继续。**明确点击停止或在板上运行 `uav-record stop all` 才结束**。断线显示状态未确认；重连重新查询，不自动重复开始。主控重启后默认不录像。

数据盘未挂载或可用空间低于 10 GiB 时拒绝开始/停止写入，不删除旧文件、不改存系统盘。控制和状态用少量网络数据，录像视频不另经 MK22。原电脑本地录像入口保留，新入口独立。

## 板端准备

新主控完整安装包含开机启动的 `uav-record-api.service`（TCP 9072），录像实例仍手动开始。104 无需重装。其他已有 uav-switch 的主控在完整 v1.3.0 解压包内运行：

```bash
sudo python3 install_record_api.py
systemctl is-active uav-record-api.service
sudo cat /etc/uav-record-api/token
```

增量安装检查已有文件和端口，不重启视频或改方案。每板独立连接码；接口只接受固定录像流的开始/停止/查询，不执行任意命令。使用 MK22/Wi-Fi 载荷网络，不向互联网开放。

## 验证及构建

原 Qt 视频逻辑 27 项、新控制器 8 项、实际 QML 面板 3 项测试通过，各含初始化/清理。控制器覆盖真实 HTTP JSON、鉴权失败、切主控的旧响应隔离、关闭不停止、重复点击和记住连接；实际 QML 面板加载并验证按钮动作。

104 用生产 Qt 控制器启动下视、预览和缺席红外，前两路确认写帧；只停止预览后下视继续，最后本次各路全部停止。源视频 PID 不变，保存文件解码通过。板端 Python 63 项通过。
