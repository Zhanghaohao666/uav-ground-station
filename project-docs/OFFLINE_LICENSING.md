# 离线授权激活

自 v1.01.12-offline-license-rc2 起，正式地面站运行前需要导入绑定本机的授权。
全程不需要互联网，不改变 MK22 地址、两套载荷方案、按需高低清切换、控制和板端录像。

## 客户端操作

1. 完整解压新运行包，关闭旧地面站，运行 `NexusGround.exe`。
2. 未激活时只显示激活窗口，不启动视频接收、控制连接或设备工具箱。
3. 点击“导出授权申请”，将 `.ngreq` 文件发给管理员；也可以复制完整 `NGL1-...` 机器码。
4. 收到管理员签发的 `.nglic` 文件后，点击“导入授权”。成功后直接进入地面站。
5. 下次启动会自动验证已保存的授权，不需要重复导入；不需要连接互联网。

运行同目录 `License-Information.cmd` 或 `NexusGround.exe --license` 可查看授权对象、编号、有效期并导入续期授权。
直接双击 `.nglic` 不会安装授权，应从地面站窗口导入。

授权保存在当前 Windows 用户的本地数据目录 `NexusGround/Licensing/license.nglic` 中，
通常为 `%LOCALAPPDATA%\NexusGround\Licensing\license.nglic`。
它与视频配置、QSettings 和运行包目录分开；升级程序、切换方案、清理软件设置不会主动删除授权。
同一台电脑换 Windows 账号时，需要在新账号下重新导入同一份授权。
重装 Windows、换主板或固件身份变化可能改变机器码，需要重新签发。

永久授权没有到期日；限期授权在启动时检查。已经进入地面站的会话不会因为时间到期或互联网断开突然停止，
下次启动再要求续期。日期有效期按中国时区计算，填写 `2030-01-01` 表示含当天，至次日零点到期。
系统时间明显早于签发时间时会拒绝授权，请校准本机时间。

## 管理员操作

客户运行包只有验证公钥，没有私钥及签发工具。管理员工具单独分发，不应与客户运行包放在一起。
Windows 管理员工具 `NexusLicenseAuthority.exe` 可直接运行，无需 Python 或 Qt。

1. 打开管理员工具，选择本版地面站对应的 `owner-key.private.pem`。
2. 导入客户的 `.ngreq` 文件，机器码会自动填写，并检查申请的密钥编号。
3. 填写授权对象，按需填写到期日期；留空为永久授权。
4. 点击“生成授权文件”，保存为 `.nglic`，只把此文件交给客户。

私钥可放在管理员工具同目录，文件名为 `owner-key.private.pem` 时自动选择。
如果私钥使用密码加密，还需填写私钥密码。申请文件内容是申请人的输入，签发前仍需人工确认授权对象。
一个授权只绑定一台电脑；同一个人使用两台电脑，应分别收集机器码、签发两份授权。
已有文件禁止直接覆盖，应使用新文件名保存续期授权，便于留存记录。

Linux/命令行也可签发：

```bash
python3 -m pip install -r tools/licensing/requirements.txt
python3 tools/licensing/license_authority.py issue \
  --private-key /安全目录/owner-key.private.pem \
  --request /申请目录/NexusGround.ngreq \
  --customer '授权对象' \
  --out /输出目录/客户授权.nglic
```

指定到期日期时增加 `--expires 2030-01-01`；密码加密的私钥增加 `--ask-password`，在交互提示中输入。
也支持 `--machine 'NGL1-完整机器码'` 替代 `--request`。

首次部署密钥时使用 `init`，私钥必须位于 Git 仓库外；**已有部署禁止重复初始化或随意换公钥**。
更换签发密钥并重新编译会导致旧授权无法验证，应作为单独迁移事项处理。
定期单独备份私钥。私钥丢失后无法继续签发匹配当前客户端的授权；私钥泄漏后他人可能签发授权。
公开 CI 仅编译不含私钥的签发工具，测试使用临时密钥，生产程序不信任临时测试密钥。

## 实现与边界

- 授权数据使用 RSA-3072 / PSS / SHA-256 签名，固定 32 字节 salt；Windows 使用系统 CNG 验签，Linux 使用 OpenSSL。
- 客户端只信任编译内置的公钥，不接受授权文件或环境变量传入的替代公钥，不提供通用激活码和跳过授权开关。
- Windows 机器码由系统安装标识及可读的 SMBIOS UUID 摘要生成，申请文件不导出原始硬件标识。
  机器码不随软件版本、软件目录或网卡切换变化；无可靠系统安装标识时拒绝激活。
- 验签通过后才解析授权策略，检查产品、本机、功能和日期；保存采用原子替换，导入坏文件保留现有好授权。
- 授权只在启动阶段检查，不增加视频逐帧处理或联网心跳，不修改板端程序。
- 离线授权无法立即远程撤销；本机时间没有可信在线时钟，不能宣称绝对防回拨、绝对防破解。
- 已公开的旧运行包仍可使用；公开源码也可被修改并重新构建。这一功能限制本版官方运行包的普通复制使用。
- 此功能不保护板端 RTSP/TCP 服务，其他播放器或客户端能否访问板端仍取决于板端认证配置。
- 项目及依赖的开源许可继续保留。具体商业发行方案需结合 `COPYING.md`、Qt 模块及其他依赖核对；新增激活不改变这些许可。

## 验证范围

自动测试覆盖有效/永久授权、到期边界、错误电脑、错误签发者、文件篡改、错误产品/功能/格式、
保存和重启读取、写入失败、非法导入保护、申请导出、激活窗口禁止进入和继续前复验。
Windows 流程还检查真实 CNG 验签、生产 EXE 未授权时停留在激活窗口，以及现有视频原生解码和环境隔离。
CI 不持有生产私钥，生产 EXE 的实际授权后主界面及用户电脑视频播放仍需用真实机器码现场验收。
